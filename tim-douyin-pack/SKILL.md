# Tim Douyin Pack Skill

将一篇较长文本（演讲稿、文章、随笔、笔记）改造成适合短视频传播的内容包，默认输出为 Obsidian Markdown。

## 适用场景

当用户提出以下需求时，优先使用本 skill：

- “把这篇演讲稿改成短视频脚本”
- “改成更适合抖音的版本”
- “给这段内容加分镜、画面和 BGM”
- “把文章包装成短视频内容方案”
- “做一个 Tim / 影视飓风感的短视频脚本包”

## 输入类型

支持以下输入来源：

1. 当前笔记（默认优先）
2. 用户指定的 `.md` 文件
3. 用户在消息中直接提供的文本
4. 用户选中的编辑器内容（若有 `<editor_selection>`）

## 默认输出内容

除非用户明确缩减，否则默认产出以下模块：

1. 短视频口播稿
2. 抖音冲突强化版
3. 分镜脚本
4. 画面建议
5. BGM 建议
6. 转场建议
7. 字幕样式建议
8. 封面标题建议
9. 剪辑节奏建议
10. 可拍摄版执行表

## 风格目标

默认采用以下组合风格：

- **叙事气质**：Tim / 影视飓风式，有画面感，有情绪推进
- **传播逻辑**：适配抖音，强调前 3 秒钩子、冲突、反转、停留感
- **语言策略**：短句、强对比、适度金句化、方便字幕切分

如果用户有额外要求，可切换为：

- 更像抖音（更强冲突、更高密度）
- 更像 B 站（更有思考感、铺垫更长）
- 更像演讲切片（保留原文气质）

## 工作流程

请严格按照下面流程执行。

### 第一步：确认输入上下文

优先级如下：

1. 若用户给了 `<editor_selection>`，优先使用选中文本
2. 若用户提到“当前文档 / 当前笔记”，读取当前笔记
3. 若用户用 `@文件名.md` 提到文件，读取该文件
4. 若用户直接贴了原文，则直接基于原文工作

如果内容来源不明确，先提一个最小澄清问题，不要盲目写作。

### 第二步：提炼原文骨架

在真正改写前，先快速识别：

- 核心主题是什么
- 最值得放大的冲突是什么
- 原文里是否有可视频化的故事场景
- 哪一句适合做开头钩子
- 哪一句适合做结尾金句

不需要把这一步显式写给用户，除非用户要求展示过程。

### 第三步：生成短视频口播稿

先给出一个可直接口播的短视频版本。

要求：

- 默认控制在 60～90 秒
- 使用短句，适合字幕切分
- 前 3 秒必须尽快出现核心矛盾或反问
- 中段必须有一个具体场景、案例或人物动作
- 结尾必须能落到一句有停留感的问题或金句

### 第四步：强化为抖音传播版

若用户要求“更强冲突感 / 更适合抖音 / 更炸一点”，则进一步增强：

- 对立更强
- 句子更短
- 钩子更靠前
- 价值反转更早出现
- 适当增加“你以为…但其实…”式结构

注意：

- 不要为冲突而失真
- 不要无意义喊口号
- 不要把内容写得像廉价鸡汤

### 第五步：补充分镜脚本

将口播内容拆成分镜，推荐格式：

- 镜头编号
- 画面内容
- 屏幕字幕
- 对应口播
- 节奏说明

镜头脚本要考虑手机短视频观看习惯：

- 高频切换
- 第一屏可读
- 视觉信息不要太满
- 反转处要留停顿

### 第六步：补画面与声音设计

默认补以下内容：

#### 画面建议

说明每一段适合什么素材，例如：

- 人物直视镜头
- 城市通勤空镜
- 医院走廊 / 教室 / 办公室
- 数据流、AI 界面、屏幕录制
- 手部特写、眼神特写、环境细节

#### BGM 建议

按段落推荐配乐气质，而不是强行给具体歌名：

- 压迫感电子氛围
- 节奏型 trap / future bass
- 留白钢琴 / 电影感氛围
- 克制弦乐收束

#### 转场建议

可使用：

- 鼓点卡切
- 闪白
- 故障感
- 静音停顿
- L-Cut 音频先行
- 黑场收尾

### 第七步：生成可拍摄版执行表

如果用户要求“可直接拍”“给剪辑师/摄影师可执行版本”“做成表格版”，则必须额外输出一个表格。

推荐字段：

- 镜头
- 时长
- 台词 / 口播
- 画面
- 景别
- 运镜
- 字幕
- BGM / 音效
- 转场
- 备注

表格目标：

- 摄影能直接按镜头拍
- 剪辑能直接理解节奏
- 口播者知道每句该落在哪个镜头
- 用户可以直接复制到 Obsidian、飞书或表格工具继续加工

推荐的字段解释：

- **镜头**：镜头编号，方便沟通与返修
- **时长**：建议秒数，帮助控制总时长
- **台词 / 口播**：当前镜头对应的核心话术
- **画面**：拍什么、放什么素材
- **景别**：特写 / 中景 / 远景 / 屏幕录制 / 空镜
- **运镜**：推近、拉远、手持、静止、快切等
- **字幕**：屏幕上最值得突出的那一句
- **BGM / 音效**：该镜头的音乐气质或音效点
- **转场**：如何衔接到下一镜头
- **备注**：补充说明，如“此处停顿半拍”“这里建议黑场”

### 第八步：输出到 Obsidian 笔记

如果用户要求写入当前文档或某个笔记：

1. 必须先读取原文件
2. 采用增量追加或局部替换，避免误覆盖其他内容
3. 使用清晰标题组织结构，例如：
   - `## 短视频脚本`
   - `### 版本一｜口播稿`
   - `### 版本二｜分镜脚本`
   - `### 版本三｜画面 + BGM + 转场建议`


## 质量标准

输出前自检：

- 开头是否足够快地产生钩子？
- 是否有至少一个“可拍”的具体场景？
- 是否能听起来像人说的话，而不是书面说明？
- 是否适合手机端逐句字幕呈现？
- 是否既有传播性，也保留原文的思想内核？

## 不要这样做

- 不要一上来就写成空泛口号
- 不要把每一段都写得同样高强度，缺少呼吸
- 不要输出全是概念、没有场景
- 不要堆砌流量词而丢掉逻辑
- 不要覆盖用户原文，除非用户明确要求整篇重写

## 推荐的澄清问题

如果信息不足，只问最少的问题。优先问这些：

1. 你要做 30 秒、60 秒还是 90 秒？
2. 更偏抖音冲突感，还是更偏 B 站叙事感？
3. 写到当前文档，还是单独新建一篇？

## 一句话用法

当用户说“把这篇内容改成更适合抖音的短视频脚本，并补上分镜、画面和 BGM”时，直接启用本 skill。
